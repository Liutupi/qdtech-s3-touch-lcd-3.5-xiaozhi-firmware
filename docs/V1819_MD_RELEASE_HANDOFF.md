# v1.8.19 世嘉 MD 双模式发布交接

日期：2026-08-08

## 发布结论

v1.8.19 在 v1.8.18 已验证功能基线上加入独立 MD 模拟器模式，并保持主 App 的 `ota_0` / `ota_1` 地址和 7 MiB 容量不变。主 App 普通 OTA 与 MD 模拟器镜像严格隔离，OTA 选择逻辑不会把 1 MiB 的 `mdemu/ota_2` 当作主固件目标。

本版明确支持两种设备状态：

1. 旧生产分区板：可从 v1.8.18 普通 OTA 到 v1.8.19；因为没有 `mdemu` 分区，系统会隐藏 MD 入口，其余主系统功能照常使用。
2. 双模式板：已通过 USB 安装尾部 `mdemu` 分区和有效模拟器镜像，OTA 更新主 App 后仍显示 MD 入口并继续使用原模拟器。

这使现有批量设备可以安全收到 v1.8.19，而不会因缺少模拟器分区出现白屏。分区表不能由普通 App OTA 改写，所以旧板首次增加 MD 模式仍必须 USB 完整刷机。本版没有实现模拟器独立 OTA，也不宣称一次普通 OTA 能把旧板变成双模式板。

## 分区与升级边界

双模式完整分区只在原 16 MiB 生产布局尾部新增：

```text
mdemu, app, ota_2, 0xF00000, 0x100000
```

原主槽保持：

```text
ota_0, 0x100000, 0x700000
ota_1, 0x800000, 0x700000
```

`GetNextMainOtaPartition()` 只允许主固件在这两个固定主槽间更新。UI 还会检查 `mdemu` 的标签、子类型、地址、大小和 App 描述，全部有效才显示 MD 入口。该检查兼容旧分区表，不读取或改写 NVS。

## 运行与安全返回

- 主系统从 SD 卡 `/roms/md/` 读取最多 128 项目录，目录缓存只在页面打开时使用 PSRAM。
- 启动前验证 ROM 路径、当前主槽、模拟器镜像和原子交接文件；任一失败都留在主系统。
- 模拟器只在自己确实运行于 `mdemu` 时启用集成直启和返回逻辑。
- 正常退出先完成一次持久化状态保存，再验证并选择进入前的 7 MiB 主槽；主槽无效时停止，不进入重启循环。
- 返回成功会写一次性 Wi-Fi 宽限标记，仅下一次主系统启动延长已保存网络的连接等待；普通冷启动路径不变。

## 已完成验证

- 主固件完整构建通过，版本为 1.8.19。
- 主 App 6,862,048 B，7 MiB 主槽剩余 477,984 B，SHA-256 为 `62D4FE98DB4E393E3990FD5E8F29BD780E98FA4200AC099F095E2C8B2B6B815E`。
- Gwenesis App 999,840 B，1 MiB 分区剩余 48,736 B，SHA-256 为 `3C1A8ED7F4E695EBCEE71C1E7056EDD094512664975EF285A4402098BE0A9842`。
- 12 项主固件双模式契约、MD 原型安全检查、70 项模拟器目标守卫和触控布局测试通过；源码树不含 ROM。
- COM12 实机已把最终主 App 写入 `0x100000` 和 `0x800000`，两段均通过回读哈希验证。
- 实机启动日志确认 App 版本 1.8.19、8 MiB PSRAM、BMI270、SD 卡和 `MD emulator installed=1`，无崩溃或看门狗复位。
- 当前板保存的 `liutupi` 网络在 8 秒窗口内未完成关联，随后按既有逻辑正常进入 `Xiaozhi-8BFD` 配网模式。发布前没有把这次路由器关联失败误判为 MD 回归，也没有扩展本版的 Wi-Fi 修改范围。

## 发布物

- `qdtech-s3-touch-lcd-3.5-v1.8.19-app.bin`：普通 OTA 和 App-only 更新，只更新主系统。
- `qdtech-s3-touch-lcd-3.5-v1.8.19-full.bin`：一次性 USB 双模式完整镜像。
- `qdtech-s3-touch-lcd-3.5-v1.8.19-firmware.zip`：分离烧录文件和说明，含独立 `mdemu.bin`。
- `qdtech-s3-touch-lcd-3.5-v1.8.19-md-source.zip`：本次独立模拟器修改对应源码及许可证，满足再分发边界。
- `SHA256SUMS.txt`：全部发布物校验值。

发布物不包含商业 ROM。模拟器保持为独立 App 镜像，相关 Retro-Go / Gwenesis 源码和许可证单独提供，不把其代码静态并入 MIT 主 App。

## 发布后多板 OTA 验收

1. 取一块仍为 v1.8.18、未安装 MD 分区的板子，联网后执行“检查更新”。
2. 确认发现 v1.8.19，下载的附件是精确命名的 App 镜像，并通过 `SHA256SUMS.txt` 校验。
3. 重启后确认版本 1.8.19、原有功能正常，且“更多”页不显示不可用的 MD 入口。
4. 取一块已完整安装双模式的板子执行同样 OTA，确认更新后 MD 入口仍存在，完成一次启动、自动存档、退出和 Wi-Fi 回连。
5. 观察 GitHub Release 下载地址和固件检查 API，确认 `v1.8.19` 标记为最新正式版而非草稿或预发布。

## 回滚

- 主系统回滚：App-only 写回 v1.8.18 到主 OTA 槽，不擦除 NVS 和 SD 卡。
- 双模式板只回滚主 App 时，可保留 `mdemu`；v1.8.18 不会使用它。
- 若要恢复原生产分区表，必须通过 USB 同时恢复生产分区表和有效主 App；不能依靠普通 OTA 改分区表。
