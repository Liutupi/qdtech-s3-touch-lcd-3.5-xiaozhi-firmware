# v1.8.18 世嘉双模式分区与安全切换交接

日期：2026-08-07

## 当前范围

当前已完成默认关闭的实验分区、主固件 OTA 隔离、SD 卡交接文件与安全切换骨架，以及主系统里的 MD 游戏目录和启动入口。没有修改模拟器运行逻辑，没有实现存档、返回主系统或双镜像远程更新，也没有烧录设备。

实验项为 `CONFIG_QDTECH_EXPERIMENT_MD_DUAL_MODE`，默认 `n`。只有在 v1.8.18 发布配置后追加 `sdkconfig.md-dual-mode.defaults` 才会启用。

## 分区与 OTA 安全边界

生产分区文件 `partitions/v1/16m_qdtech_7m_ota.csv` 未修改。实验分区表保留原六项地址和大小，只在 16 MiB Flash 尾部增加：

```text
mdemu, app, ota_2, 0xF00000, 0x100000
```

必须使用 `ota_2`，不能改成 `factory`。验证过程中发现，存在 factory App 时 ESP-IDF 会把主固件默认烧录目标改到 factory；对于 1 MiB 的 `mdemu` 会生成错误烧录参数。改为 `ota_2` 后，两套最终 `flash_args` 均确认主 App 写入 `0x100000`。

实验开启时，`GetNextMainOtaPartition()` 只允许当前主固件在 `ota_0` 与 `ota_1` 之间互相更新，并校验两槽固定地址及 7 MiB 大小。普通 OTA、固件页容量检查和诊断页的“下一槽”均不会选择 `mdemu/ota_2`。实验关闭时仍编译原 `esp_ota_get_next_update_partition()` 路径。

## 安全交接服务

板级 `MdBootService`：

- 只接受 `/sdcard/roms/md/` 下的普通文件。
- 拒绝空组件、`.`、`..`、反斜杠、盘符和目录穿越。
- 只接受 `.md`、`.gen`、`.bin`、`.smd`、`.zip`，扩展名不区分大小写。
- 切换前验证当前主固件确实运行在 `ota_0` 或 `ota_1`。
- 验证 `mdemu` 是 `ota_2`、地址 `0xF00000`、大小 `0x100000`，并能读取有效 App 描述。
- 原子写入 `/sdcard/retro-go/config/md_handoff.json`，内容包括相对 ROM 路径、`fresh/resume`、0–3 存档槽和准确的返回主槽。
- 临时文件完成 `fflush`、`fsync` 和 `rename` 后，才调用 `esp_ota_set_boot_partition(mdemu)`。
- 服务不自动重启，不创建任务、定时器、队列、信号量或常驻缓冲区。

## 主系统游戏目录与启动入口

- “更多”页在实验开关开启时增加“MD 游戏”卡片；实验关闭时原界面和原构建完全不变。
- 游戏页只在打开时创建，关闭时立即释放页面对象和目录缓存。
- 优先读取 `/sdcard/roms/md/catalog.tsv` 中的中文名称与分类；目录文件缺失或无有效条目时，回退扫描 `/sdcard/roms/md` 根目录及一层子目录。
- 支持 `.md`、`.gen`、`.bin`、`.smd`、`.zip`，最多载入 128 项。
- 目录数组固定使用 PSRAM，最大 40,960 B；加载 TSV 时另有 1,024 B 临时 PSRAM 缓冲，加载结束即释放。
- 每页显示五个游戏，支持上下翻页、当前选择、新游戏/继续游戏和 1–4 存档槽。
- “启动”目前只调用可注入回调；没有回调时显示“启动接线待下一阶段完成”。本阶段不会设置启动分区、重启或进入模拟器。
- 没有新增任务、任务栈、定时器、队列、网络请求、音频路径或传感器采样。

## v1.8.18 完整发布组合验证

验证配置包含已发布并验收的称骨、星座、电台目录、益智游戏馆、伪 3D 骰子、摇一摇全屏、木鱼及木鱼音效。关闭态构建的 `.bin` 大小和六段镜像布局与 v1.8.18 发布成品完全一致；SHA256 因本次重新构建的镜像元数据而不同，不把哈希相同作为基线判断条件。

| 项目 | 双模式关闭 | 双模式开启 | 增量 |
|---|---:|---:|---:|
| App `.bin` | `0x6869A0` / 6,842,784 B | `0x688FB0` / 6,852,528 B | 9,744 B |
| 7 MiB 主槽剩余 | `0x79660` / 497,248 B | `0x77050` / 487,504 B | -9,744 B |
| 未填充镜像 | 6,842,587 B | 6,852,327 B | 9,740 B |
| Flash `.rodata` | 4,669,352 B | 4,671,196 B | 1,844 B |
| Flash `.text` | 2,045,060 B | 2,052,956 B | 7,896 B |
| DIRAM | 172,327 B | 172,327 B | 0 B |
| `.bss` | 44,408 B | 44,408 B | 0 B |
| `.data` | 29,016 B | 29,016 B | 0 B |

常驻内部 SRAM、静态 PSRAM、任务和任务栈增量均为 0。游戏目录页面打开时最多使用 40,960 B PSRAM 保存 128 项目录；解析 TSV 时峰值再增加 1,024 B，随后释放。LVGL 页面对象也只在目录页打开期间存在，其实际动态堆峰值需上板测量。

尺寸工具会警告 1 MiB `mdemu` 小于 6.5 MiB 主 App，因为它会用主 App 对所有 App 分区做通用比较；构建返回成功，主 App 烧录地址是 `0x100000`。已验证的 Gwenesis App 为 995,200 字节，SHA256 为 `5D67F3B4F800D85F668239079C188F8C1BB21AE635F3F46404B7FE45D0420D1A`，放入 `mdemu` 后余 53,376 字节。

自动契约测试共 7 项，覆盖分区、默认关闭、ROM 路径、无后台运行时、安全切换顺序、普通 OTA 回退路径、PSRAM 有界目录和启动入口不切换分区，全部通过。`git diff --check` 通过，仅有仓库原有的 LF/CRLF 提示。

## 回滚

未烧录前，只需不加载 `sdkconfig.md-dual-mode.defaults`，实验代码和分区均保持关闭。

若以后已经烧录实验分区表，不能只刷默认关闭 App 后继续保留三 OTA 表。应在同一条 esptool 写入命令中恢复生产分区表到 `0x8000`，并把已验证的 v1.8.18 App 写回 `0x100000` 与 `0x800000`。不要执行全片擦除，不要擦除 NVS。
