# v1.8.18 世嘉模拟器直启、存档与安全返回交接

日期：2026-08-07

## 本阶段完成内容

本阶段继续使用默认关闭的 `CONFIG_QDTECH_EXPERIMENT_MD_DUAL_MODE`，完成主固件游戏入口到独立 Gwenesis 镜像的真实启动链路，以及模拟器退出时自动存档并返回原主固件槽位。没有实现主固件与模拟器的双镜像远程升级，没有烧录、提交、推送或发布。

主固件点击“启动”后，触控回调只把请求投递到 Xiaozhi 主事件循环。主循环依次验证 ROM、当前 `ota_0/ota_1`、`mdemu` 镜像和原子交接文件；全部成功后才停止电台、播客和 FC 模拟器，调用 `Application::PrepareForFirmwareUpgrade()` 关闭语音与协议链路，最后重启。验证失败会清除防重复标志并留在主系统，不会停止现有服务或切换启动分区。

## 直启与安全返回

Gwenesis 仅在当前运行分区同时满足以下全部条件时进入双模式：

- 标签为 `mdemu`；
- App 子类型为 `ota_2`；
- 地址为 `0xF00000`；
- 大小为 `0x100000`。

独立实验板原有的启动器行为不受影响。双模式下，模拟器从 `/sd/retro-go/config/md_handoff.json` 读取最多 2 KiB 的交接信息，严格校验 schema、目标、ROM 相对路径、`fresh/resume`、0–3 槽位和返回标签，然后直接载入 `/sd/roms/md/` 下的选定游戏。

退出时先在 SD 卡仍挂载的状态下触发一次关闭事件，自动保存当前槽位，再验证并选择主固件。返回候选顺序为交接指定槽、主交接、备份交接、`ota_0`、`ota_1`；每个候选都必须匹配生产地址、7 MiB 大小、OTA 子类型并具有有效 App 描述，最终仍由 ESP-IDF 在切换启动分区时验证镜像。若两个主槽都无有效镜像，模拟器停止运行而不是重启循环。

## 存档语义

安全退出会保存完整模拟器状态，可保留需要存档的游戏进度。文件位于：

```text
/sd/retro-go/saves/md/<ROM 在 roms 目录内的路径>.sav
/sd/retro-go/saves/md/<ROM 在 roms 目录内的路径>-1.sav
/sd/retro-go/saves/md/<ROM 在 roms 目录内的路径>-2.sav
/sd/retro-go/saves/md/<ROM 在 roms 目录内的路径>-3.sav
```

槽 1（内部编号 0）没有数字后缀，槽 2–4 分别使用 `-1`、`-2`、`-3`。写入过程继续使用 `.new`、`.bak` 和重命名，Gwenesis 写完 `.new` 后新增 `fflush` 与 `fsync`；重复关闭事件不会重复保存。刚在菜单中保存完成后两秒内退出时会跳过重复自动保存。

当前实现是完整状态存档，不宣称支持卡带原生 SRAM。正常触控退出或菜单退出可自动保存；突然断电、硬件复位或模拟器崩溃发生前无法保证保存最新进度。崩溃恢复会优先安全返回主系统，但不会把崩溃瞬间的状态写入存档。
