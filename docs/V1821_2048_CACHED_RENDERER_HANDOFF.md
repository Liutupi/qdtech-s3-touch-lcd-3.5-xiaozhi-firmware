# v1.8.21 2048 单帧缓存渲染与输入背压交接

日期：2026-08-11

## 问题与边界

v1.8.21 已减少 2048 的阴影、高光和无效方向重绘，但用户确认长时间连续操作仍会卡死。棋盘状态本身是固定数组，移动过程不需要动态内存；剩余高风险点是每次有效移动仍在 LVGL 全屏刷新路径中创建大量矩形和文本绘制任务，以及顶部状态标签的反复文本分配。

本阶段只修改 2048。其他益智游戏、主题、触摸解析、Wi-Fi、天气、语音、音频、电台、日历、摇一摇、OTA、分区和 MD 双模式保持不变。

## 实验实现

- 开关：`CONFIG_QDTECH_EXPERIMENT_2048_STABLE_RENDERER`，默认关闭并依赖益智游戏馆。
- 进入 2048 时在 PSRAM 创建 `480 × 266 × RGB565` 画布，固定占用 255,360 字节；退出页面立即删除画布并释放缓冲。
- 静态面板和按钮只绘制一次；每步只把发生变化的方块与分数区域同步画入缓存。
- 每个方块使用独立 canvas layer 并在继续前完成，限制同时存在的临时绘制任务；显示侧只提交画布图像。
- 90 ms 输入间隔用于阻止刷新突发持续排队。
- 每 32 次有效移动记录内部 SRAM、最大连续块、历史最低值、PSRAM、拒绝输入数和渲染耗时，不新增任务或定时器。
- 画布或渲染器对象分配失败时继续使用 v1.8.21 原自定义绘制路径。

## 验证与回退

- 纯 C++ 棋盘逻辑执行 10,000 次随机操作并检查数值、合并和不可移动状态。
- 静态守卫检查默认关闭、PSRAM 分配、输入背压、诊断、释放和回退路径。
- 必须分别完成开关关闭和开启的 ESP-IDF 构建。
- 实机只刷 App；不写 NVS、分区表、bootloader 或 `mdemu`。
- 实机目标：联网连续操作至少 1,000 次或 20 分钟，退出/重进 10 次后 PSRAM 回收且内部最大连续块不持续下降。
- 一步回退：关闭实验开关重新构建，或仅刷回 GitHub v1.8.21 App。

## 方向键与历史纪录补丁

- 首轮实机验证完成 42 个有效移动，第 32 步渲染约 10.7 ms，缓存正常释放，无崩溃、看门狗或重启。
- 修复动态信息区覆盖上方向键的绘制顺序/坐标冲突；方向键改为独立的 `y=62/104` 两行，触控命中区同步。
- 新增历史最高分，使用独立 NVS 命名空间 `puzzle2048`、键 `high_score`。
- 纪录只在提高时标记为待保存，退出 2048、重开或游戏结束时提交，避免每一步写 Flash。
- NVS 失败仅记录警告，不使用致命检查，不影响游戏和 v1.8.21 回退路径。
