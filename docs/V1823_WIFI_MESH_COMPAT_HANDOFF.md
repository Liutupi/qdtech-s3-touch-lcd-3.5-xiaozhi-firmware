# v1.8.23 路由器与 Mesh Wi-Fi 兼容优化交接

## 目标与边界

本版本建立在已发布的 `v1.8.22` 上，解决少数路由器或 Mesh 环境中“手机能看到 Xiaozhi 配网热点、提交密码后板子仍无法联网”的问题。改动仅位于 QDTech Wi-Fi 配网和重连路径，不改变桌面 UI、触摸、BMI270、天气、音频、日历、益智游戏、MD 双模式、分区表或 SD 卡资源。

## 故障特征与处理策略

- 对同一 SSID 的多个 BSSID 先按 RSSI 排序，再固定到具体节点；失败后轮换候选，避免一直重试同一个 Mesh 节点。
- 配网页面把“已关联”与“已拿到 DHCP 地址”分开判断，只有拿到地址才报告成功。
- 正常 802.11 b/g/n 连接失败后，只有事件全部为 `AUTH_EXPIRE` 且从未完成关联，才尝试旧式 b/g 配置。
- 如果正常模式和旧式模式都满足同一严格条件，写入一次 `alt_sta_mac` 标记并延迟重启。重启后只对 Station 接口使用由工厂 MAC 确定生成的本地管理地址；SoftAP 和工厂地址不变。
- 标记已存在时不会重复安排重启，防止启动循环。用于实验的强制开关 `CONFIG_QDTECH_EXPERIMENT_ALTERNATE_STA_MAC` 默认为关闭。

## 稳定性与资源影响

- 没有新增常驻任务、定时器、队列、音频客户端或 UI 对象。
- 仅在配网彻底失败、即将重启时创建一次 3072 字节临时任务；延迟约 1.5 秒后重启，正常运行不保留该任务。
- 复用既有 NVS 分区和 Wi-Fi 组件；不擦除用户网络、激活信息或 SD 卡数据。
- 非 QDTech 板型和关闭 `CONFIG_QDTECH_PROVISIONING_COMPAT` 的构建保持原行为。

## 验证记录

- 目标板：ESP32-S3，16 MB Flash，8 MB PSRAM，COM12；工厂 MAC `7c:e8:b1:b2:8b:fc`。
- 兼容身份路径：Station `7e:e8:b1:b2:8b:fc` 连接 `liutupi` / BSSID `fc:94:35:08:0a:e8`，获得 `192.168.4.125`；OTA 检查、MQTT、天气 HTTP 200 和时间同步均成功。
- 清空 NVS 后首次配网：热点 `Xiaozhi-8BFD` 可加入，提交 `liutupi` 后原始身份直接获得 `192.168.4.126`，随后 OTA、MQTT、天气和时间同步成功。
- 恢复测试前 NVS 后，原 UUID、兼容身份和 `192.168.4.125` 恢复，服务再次全部通过。
- `tests/qdtech_wifi_mesh/test_wifi_mesh_fallback_contract.py` 共 11 项测试全部通过。
- ESP-IDF 5.5 正式构建通过，项目版本为 `1.8.23`；App 为 7,064,592 字节（`0x6bcc10`），7 MB OTA 槽剩余 275,440 字节（`0x433f0`）。
- 完整双模式镜像为 16,728,480 字节；`ota_0` 与 `ota_1` 中的 App SHA256 均与发布 App 完全一致，`mdemu` 分区与已验证的 v1.8.21 镜像完全一致。

## 验证边界

清空 NVS 的最后一轮测试中，路由器已经重新接受原始 Station 身份，因此没有再次自然触发“原始身份连续失败后自动切换”的完整端到端过程。严格失败判定、标记写入/单次重启保护与兼容身份启动已分别通过契约测试和实机验证。后续应在仍能稳定复现该路由器拒绝现象的现场补录一轮完整自动切换日志，但这不影响普通配网和已验证兼容路径的发布。

## 回滚

OTA 安装 `v1.8.22` App 镜像即可回滚代码并保留 NVS 与 SD 卡。若需要停用兼容身份，可清除对应 NVS 标记或进行明确授权的完整恢复；不要为了普通 OTA 回滚擦除整片 Flash。
